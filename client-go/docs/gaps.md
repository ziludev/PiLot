# 第一版客户端有、这个客户端还没搬的东西

`94c8c28` 把桌面客户端重写成三块（rail / transcript / composer）。这份文件原来是「缺什么」的待办，
现在改成「为什么不做」的账：剩下的每一条都评估过，结论是不搬。

**服务端接口全都还在——这正是陷阱。** 接口在只说明搬得动，不说明搬来有用。判断标准只有一条：
**它能不能省掉一个真实会跑的动作**。省不掉的，哪怕代码只差五十行也不写：多一个能点的东西，
就多一处会看错的地方，还多一份要维护的语义。

## 1. 搬回来了（都在这一轮之前或这一轮里，附验收过的证据）

| 能力 | 落在哪 | 为什么它过得了上面那道尺子 |
| --- | --- | --- |
| 改动 / 全文两栏 | `changes.go` 的 `fileTextView` | diff 回答「动了什么」，全文回答「现在写着什么」——读 diff 去回答后者是猜。停在这一步，不加搜索/高亮/跳转：那是编辑器的活 |
| 提交 / 推送 / 合并 | `gitwrite.go` | 省掉「看完 diff 切终端输三条 git」。三个动词各问一次确认，拒绝理由成句留在按钮下面 |
| 项目栏 | `projects.go` | 「这个聊天生在哪个仓库」只能在开聊时定，事后 bridge 补不回来 |
| ⌘K 命令面板 | `palette.go` | 「找到上周那个会话」原来要滚侧栏、展开分组、读标题；现在打字即筛，动作和侧栏按钮共用同一个函数，不会走散。参考 Linear / VS Code / crush 的 `Ctrl+P`，选型笔记见 `docs/agent-clients-review.md` |
| 跳到文件 ⌘P | `files.go` | 把 checkout 里任意文件的绝对路径写进输入框。列表来自 `git ls-files`（含未跟踪但不被忽略的），不是目录遍历，所以 node_modules / dist 不会淹掉结果。参考 VS Code / crush 的 `Ctrl+P` |
| 置顶 + 按项目分组 | `rows.go` 的 `railShelves`、`prefs.go` 的 `Pinned`/`Group` | 置顶是一块永远在最上面的架子，钉住的聊天也永不被时间折进已归档（`pin` 只存本机，不进 bridge）。分组可以在「按来源」和「按项目」之间切，切换入口在设置里，也有 ⌘K 动词 |
| 快捷键表 ⌘⇧/ | `cheatsheet.go` | 五个键够用也够忘，叫得出来比烫在界面上便宜 |
| 记忆带出处 | `memory.go` 的 `memoryReceipt`、bridge `memory.ts` 的 `source` | 每条记忆后面写「来自 会话 #8 / 夜间整理 / 飞书备忘」，会话那条点一下就跳回去。出处由写入方盖章（`chat:<id>`、`curator`、`feishu`），不是模型自己编的；老记忆没有出处就不写，不猜 |
| 夜间静音 + 每天上限 | `notify.go` 的 `delivery`、设置里的「夜间静音」「每天最多」 | 22:00–08:00 不弹；一天最多 5 条「做完了」。**审批不受上限管**：做完了的消息在侧栏有圆点，审批是有人在那儿等你的决定，不能被一早上的完成消息挤掉。两个开关都能关掉，prefs 写坏了回落到默认而不是静音 |
| 停止之后还剩什么 | `taskdetail.go` | 停止的任务详情里明说「会话和已经改的文件都还在，接着说一句就能续」。**取消 ≠ 关闭**——不然停一次就以为自己把活丢掉了 |
| 导出为 HTML | `exporthtml.go` | 和 Markdown 同名不同后缀：原话成段落、步骤折在 `<details>`、样式内联，双击就能读，能直接发给别人 |
| 导出为 Markdown | `exportmd.go` | 给 PR、issue、不在场的人用：原话留着，步骤折起来，工具输出不带走（最长也最少被引用） |
| 拖任意文件进来 → 路径 | `actions.go` 的 `putPaths` | 图片当附件、小文本整段引用这两条不变；其余（pdf、大文件、目录）把绝对路径放进输入框。agent 就在这台机器上跑，拒绝拖拽只是逼人去复制路径 |
| 基准只读 chip | `base.go` | 改动和未合并的提交从哪儿算起，得写在数字旁边；但**不提供切换**，理由见下 |

## 2. 不做的，和原因

| 候选 | 接口 | 结论 |
| --- | --- | --- |
| 清理 worktree | `POST /api/worktree/remove`（我们的 bridge） | **不做界面，已修在 bridge**。36 个 worktree 共 2.1MB（对象库共享），33 个对得上现存会话——那是「一聊天一 checkout」的设计结果，不是泄漏。剩下 3 个孤儿是**存储被重置/迁移后 `.worktrees` 比会话活得久**：没有任何代码路径会主动删会话，所以没人回收。现在每次启动扫一遍（`reclaimWorktrees`），只删「已合进 base 且工作区干净」的，留下未合并或有未提交文件的并记一行日志。要人点按钮替机器做家务是错的 |
| 权限页 | `GET /api/access`、`/api/audit` | **不做**。`/api/access` 是飞书群聊 ACL（`closed/owner/group` + chatId→会话），`/api/audit` 是 harness 事件流水。在桌面单人客户端里管「哪些飞书群能用我」，等于把机器人后台塞进编辑器侧栏；这两件事属于飞书和 CLI |
| 每步耗时竖轨 | 无——但不需要接口 | **不做**。折叠行已经给出「4 步 · 12s」（相邻消息 timestamp 之差，数据本来就在 `/api/conversation` 里）。要查「这几分钟被谁吃了」，看日志和 spend 比在 GUI 里排一排毫秒数直接 |
| 拖拽排序 / 置顶 | 无（第一版也只是本地 prefs） | **不做**。rail 已经有分区、7 天自动归档、搜索、折叠——乱是整理问题不是排序问题，而拖拽要几百行 UI 还要和自动归档的规则打架。真嫌乱，缺的是「按天 / 按项目分组」 |
| **切基准**（本轮删掉的） | `POST /api/git/base`（我们的 bridge，且不校验分支存在） | **不做**。它不省任何一步，只改变 diff 和「未合并」列表的**含义**：base 设成 worktree 不是从那儿切出来的分支，每个提交都会变成未合并、每个文件都变成改动，而界面看起来一切正常。写操作真正合法的地方（agent 自己的 workspace）base 永远是主干；工作仓库的集成分支本来就不许从这个窗口合并 |

一句话：剩下这五条全是第一版设置页 / 管理面板的残影，没有一条对应日常摩擦。继续照清单补，
就只是把第一版的设计债一起搬进来。

## 3. 动手时别踩的坑

- **命令面板不能用 `ui.Popover`**（`internal/app/palette.go`）：Enter 要选中行，Popover 会把它吃掉。
  用 `ui.Modal` + `TextInputBase.OnTextKey` 自己拦 ↑↓ / ⏎ / esc，返回 true 表示这一下自己处理了。
- **`ui.Popover` 会把 Enter 当成自己的关闭键**。模型面板要 Enter 选中，所以它是 composer 上方的内联
  面板（`internal/app/model.go`）而不是浮层；别的面板要 Enter 也别用 Popover，或者在 Popover 里自己拦键。
- **`Exit` 动效挂在 `ui.List` 的行上不生效**（v0.10.0 仍是）：行在数据消失的那一帧就被丢掉，没有元素
  可以挂。要收拢动画就自己记账 + `AnimateTo`，或者等 `ListState.MoveAnimation` 覆盖这个场景。
- **transcript 的步骤折叠是手写的**（`rows.go` 里数 agent / tool 行数生成一行摘要）。往里面加结构化
  输出时不要改折叠结构，只在展开后的内容里分派。
- **rail 的分区是 `rows.go` 的 `chatSections` + `prefs.Sections`**。新的分区（比如「已归档」）照抄这套，
  默认折叠、点分区头开合、选过的状态进 `~/.pitta/window.json`。
- **任务行能点开**（`internal/app/taskdetail.go`）：列表回答「有没有东西坏了」，不回答「为什么」。
  对话框给类型/会话/开始时间/输入/结果/子 agent，运行中的才有「停止任务」——点完不假装停了，
  而是再问一次 bridge（abort 是异步的）。
- **用量日历**（`internal/app/usage.go`）：开销是唯一不能靠看屏幕核对的东西，所以给个形状——
  17 周 × 7 的方格，颜色由浅到深按当天花费，底下是总额/总 tokens/最贵一天。只在任务 tab 出现，
  因为它数的是那个 tab 列的工作。色阶用混色而不是 alpha：半透明叠在弹层上会糊。
- **消息操作条照 assistant-ui 的样子**（`internal/app/message.go`）：每个气泡下面都有，平时 `Opacity(0)`、
  `IgnoreInput`，指针进来才亮——所以它既不让版面跳动，也不会误点。「编辑重发」只把文字放回输入框，
  不改历史：transcript 是 agent 的记录，改过的问句会让答案对着没人说过的话。
- **回到最新的浮标**（`transcript.go` 的 `jumpToLatest`）：对话在跟随最新一轮，读者只有滚上去才能看旧答案，
  那就得给一条回来的路。查找条开着时不显示，两者抢同一个「看哪儿」。
- **文件和它的改动并排**（`changes.go` 的 `fileTextView`）：改动回答「动了什么」，全文回答「现在写着什么」，
  读 diff 去回答后者是猜。切换按钮只在 worktree 的文件上有——一个提交的 diff 背后没有「全文」这回事。
  行号放在同一串里靠 figure space 右对齐：行首普通空格会被排版吃掉，行号就会贴上文件自己的缩进。
- **写操作只问一句，做的是 bridge**（`gitwrite.go`）：提交要一句话，推送和合并各要一次确认；结果留在抽屉底部而不是
  只弹 toast —— 冲突是一串文件名，飘过去就读不到了。bridge 拒绝（工作区脏、目标分支脏、冲突）都当作可读的指令，原样显示。
  合并成功后整份重读，不照着回包改列表：分支的提交在合并那一刻就变了。
- **基准是读出来的，不是选出来的**（`base.go`）：它决定「改动」从哪儿算起、哪些提交算未合并、合并落到哪，
  所以紧挨着那三个动词、只占一行小字。**别把它做成下拉框**：bridge 不校验 base 是否存在，也不校验它是不是这条分支
  的来处，递一个不对的名字进去，抽屉从此算不出一件对的事，而且看起来一切正常。
- **项目栏在 rail 上，不在右栏的开关里**（`projects.go`）：项目不是当前这个会话的属性，它是下一个会话可能去的地方。
  点一个项目就在那儿开会话；加路径被拒时说的是「不是 git 仓库 / 没有这个目录 / 已经有了」，因为这三件事要人做的不同。
  移除项目会说它的会话挪去了内置工作区——挪走不是消失。
- **右栏是抽屉，两个抽屉轮着来**（`internal/app/changes.go`、`memory.go`）：同一个右边缘，打开一个
  就关另一个——两个 460 点的栏会把 transcript 挤成一条。窄窗口时抽屉 `Shrink(1)` 到 300，rail 的 260
  之外还得给 transcript 留活路。
- **diff 一行一个 `ui.List` 行**：一个重新生成的 lock 文件是几千行，不虚拟化就会在渲染上卡住。
- **设置收在一个面板里**（`internal/app/settings.go`）：rail 页脚现在只有一个齿轮。齿轮打开对话框时
  每帧重读 prefs，面板本身不存状态——多一份副本就会漂移。
- **查找条是手写的**（`internal/app/find.go`）：`ui.FindBar` 用窗口语言说 "1 of 3"，而这个 app 的语言
  是自己存的，中文窗口里冒出英文比多写四个小按钮更糟。命中按「行」算，滚到当前命中并给它上底色。
- **中文界面默认**，文案都走 `internal/i18n/dict.go`，zh 与 en 两套一起加；`i18n` 测试钉着键数上限
  （现在 221 = 上限），加键就抬上限并在 `maxKeys` 上写清是哪一块加的。
- **记忆抽屉是右栏，不是 rail 的分区**（`internal/app/memory.go`）：记忆是句子，260 点的 rail 会把它们
  折成一团。它跟着打开的会话走（`selectConversation` 里重读 chat 那一档），整理是一轮模型调用，所以
  按钮上写着在跑、失败也照实说。
